# SEO And Agent Discovery

This checklist is for making the repository easier to find through GitHub search, web search, AI search, coding agents, and agent crawlers.

## Primary Positioning

Use one clear phrase everywhere:

```text
Hermes Hybrid Agent Router
```

One-line description:

```text
Route cheap draft work to local Ollama and llama.cpp models, then reserve OpenAI Codex for code, config, tool use, and final decisions inside Hermes Agent.
```

Short social hook:

```text
Stop paying premium-model prices for every draft. Hermes can route local LLM work to Ollama and llama.cpp, then escalate consequential tasks to OpenAI Codex.
```

## README SEO Rules

- Keep `Hermes Hybrid Agent Router` as the H1.
- Mention `Hermes Agent`, `Ollama`, `llama.cpp`, `OpenAI Codex`, `local LLM`, `MOA`, and `agent router` in the first screen.
- Explain the cost-saving angle before the architecture diagram.
- Keep the Mermaid diagram near the top because it increases skim value.
- Put the beginner workflow before the detailed architecture so new readers understand the idea quickly.
- Link to `llms.txt`, architecture, replication guide, and sanitized routing snapshot from the README.
- Avoid keyword stuffing. Use terms in real sentences.

## Agent SEO Rules

- Keep `llms.txt` short and current.
- Keep `.github/copilot-instructions.md` aligned with `llms.txt`.
- Keep `repo-metadata.yaml` aligned with the GitHub About box and topics.
- Keep architecture and replication docs linked from both human and agent entry points.
- State safety constraints explicitly: no secrets, no raw backups, no personal memory, no silent authority fallback.
- Include concrete model/provider examples, but make clear that users can swap models.
